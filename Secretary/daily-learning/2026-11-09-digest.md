**cronとPATH管理**
• cronジョブはユーザーの `.zshrc` / `.bash_profile` を読み込まないため、PATH は `/usr/bin:/bin` 相当の最小構成のみ。`claude` や `python3`（pyenv経由）等がexit 127で無音終了する根本原因。対策はcrontabの先頭に `PATH=/usr/local/bin:/usr/bin:/bin:/opt/homebrew/bin` を明示するか、スクリプト冒頭で `export PATH=...` を宣言すること。
• macOSではAppleがcronを非推奨化し、**launchd**（plistで `EnvironmentVariables` ブロックにPATHを記述）を推奨。launchdはスリープ復帰後の実行補完やjournaldログ相当の出力分離など運用上の利点が大きい。
• デバッグ手順: `env -i PATH=/usr/bin:/bin HOME=$HOME /bin/bash /path/to/script.sh` でcronと同じクリーン環境を再現してから問題を絞り込む。変数展開不可なので `PATH=$HOME/bin:$PATH` はcrontab内では機能しない点も注意。

**`set -e` のサイレント終了とエラーハンドリング設計**
• `set -e` 単体では「失敗で終了」するがログを残さない。推奨は `set -Eeuo pipefail` ＋ `trap 'echo "ERROR at line $LINENO (exit $?)" >&2' ERR` の組み合わせ。`-E` フラグを加えることで関数・サブシェル内のERRトラップも継承される。
• ERRトラップは診断用（失敗行番号・終了コードのログ出力）、EXITトラップはクリーンアップ用（一時ファイル削除等）と役割を分けるのがベストプラクティス。EXIT内で `$?` を最初にキャプチャして最後に返すことで元の失敗ステータスを保持できる。
• `set -e` が発動しない例外: `||` / `&&` チェーン内、`if` 条件節、コマンド置換 `$(...)` のデフォルト動作。Bash 4.4以降は `shopt -s inherit_errexit` でコマンド置換にも `set -e` を継承可能。意図的な失敗は `|| true` または一時的な `set +e ... set -e` ブロックで明示的に処理する。

**git non-fast-forward push と rebase の操作順序**
• 自動化スクリプトで複数箇所からpushする場合の推奨順序: `git add → git commit → git fetch → git rebase origin/main → git push`。**commitより前にpullすると、unstaged changesがあるとrebaseが中断**されるため、必ずcommit後にrebaseすること。
• `git pull --rebase` に `--autostash` を加えると未コミット変更を自動スタッシュして安全にrebaseできる（CI/CD環境向け）。公開済みブランチ（main等）へのrebaseは他者の履歴を書き換えるため禁止。自分専用のfeatureブランチのみに適用する。
• force pushが必要な場合は `--force-with-lease` を使用（他者の変更を誤って上書きするのを防ぐ）。rebase失敗時は `git rebase --abort` でスクリプトに適切なエラーハンドリングを入れる。
