**cronとPATH管理**
• cronはユーザーの `.zshrc`/`.bashrc` を読み込まないため、`/usr/local/bin` や `/opt/homebrew/bin`（Apple Siliconでは必須）が未登録になりコマンドがexit 127でサイレント失敗する。対策はcrontab冒頭に `PATH=/usr/local/bin:/opt/homebrew/bin:/usr/bin:/bin` を明示するか、スクリプト内でコマンドの絶対パスを使う。
• macOSでの長期的な解決策はlaunchdへの移行。launchdは `EnvironmentVariables` でPATHをエージェントごとに分離設定でき、さらにMacがスリープ中に実行を逃してもウェイク後に自動リトライする（cronは逃したら消える）。Apple公式もlaunchd推奨。
• デバッグ時のコツ：cron実行をログファイルに `2>&1 >> /tmp/cron.log` でリダイレクトし、スクリプト冒頭で `env > /tmp/cron-env.log` を実行すると環境変数の差分を即確認できる。

**`set -e` のサイレント終了とエラーハンドリング設計**
• `set -e` は `if` 条件式・`||`/`&&` チェーン・サブシェル内では発火しないという落とし穴がある。`|| true` を多用するとエラーを意図的に握り潰す箇所が増え、根本的なリファクタが必要になる。
• 推奨は `set -euo pipefail` の三点セット：`-u` で未定義変数を即エラー化し、`-o pipefail` でパイプ途中の失敗を検出する。`set -e` 単体より大幅に安全。
• `trap 'echo "ERROR at line $LINENO: $BASH_COMMAND (exit $?)" >> /var/log/script.log' ERR` を冒頭に置くと、`set -e` が拾えないコンテキストでもすべてのエラーをログに記録できる。スタックトレースが必要なら `set -E` と組み合わせて `$BASH_LINENO` 配列を辿る。

**git non-fast-forward push と rebase の操作順序**
• non-fast-forwardエラーはローカルとリモートの両方に新コミットが存在して分岐した際に発生する。自動化スクリプトで「ファイルコピー → pull → commit → push」の順序を踏むと、pullの時点でコピー済みの未ステージ変更がrebaseをブロックするため、正しい順序は **pull → ファイル操作 → commit → push**。
• `git pull --rebase` がautomationスクリプトでの推奨。リモートの変更を取得してからローカルコミットをその上に積み直すため、マージコミットが生まれずに履歴が線形を保てる。botが同じ分に1ファイルだけpushしたケースではほぼ自動解消する。
• コンフリクト発生時の手順：`git add <解決済みファイル>` → `git rebase --continue`（この段階でcommitは不要）。自動化スクリプトではコンフリクトを検知したら `git rebase --abort` してアラートを出す安全弁も有効。
