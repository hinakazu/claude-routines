**cronジョブとPATH管理**
• cronのデフォルトPATHは `/usr/bin:/bin` のみ。`.zshrc` や `.bash_profile` は一切読み込まれないため、Homebrew (`/opt/homebrew/bin`) や自作ツールのパスが通らずexit 127で無音終了する。
• 解決策はcrontab冒頭に `SHELL=/bin/bash` と `PATH=/usr/local/bin:/usr/bin:/bin:/opt/homebrew/bin` を明示的に宣言すること。変数展開 (`PATH=$PATH:...`) はcron実装によって動作しないため、絶対パスで書くのが鉄則。
• macOSではAppleが `cron` を非推奨化しており、公式推奨は `launchd`。`launchd` はジョブ定義内の `EnvironmentVariables` でPATHをジョブ単位に設定でき、スリープ中に予定時刻を過ぎてもスリープ解除後に実行する（crontabはスキップ）。

**`set -e` のサイレント終了とエラーハンドリング設計**
• `set -e` はif文の条件部・`&&`/`||` チェーン・サブシェル内では**効かない**という落とし穴がある。また `(( i++ ))` のような算術式が0を返すだけでスクリプトが即終了する。
• 確実なエラーキャッチには `trap 'handle_error $LINENO "$BASH_COMMAND" $?' ERR` を組み合わせる。`-E`（errtrace）オプションを付けることで関数やサブシェル内のエラーにもトラップが継承される。
• 推奨セットは `set -eEuo pipefail` + `trap ERR`（エラーログ） + `trap cleanup EXIT`（終了時クリーンアップ）の3点セット。ログにはエラー発生行番号 `$LINENO` と失敗コマンド `$BASH_COMMAND` を含めると原因追跡が格段に速くなる。

**git自動化スクリプトの操作順序（non-fast-forwardエラー防止）**
• non-fast-forwardエラーは「ローカルにないコミットがリモートにある」状態でpushしようとしたときに発生。複数の自動化スクリプトや人間が同一ブランチにpushする環境では頻発する。
• 自動化スクリプトでの正しい操作順序は **`git pull --rebase` → ファイル操作（cp等） → `git add` → `git commit` → `git push`**。ファイル操作を先にしてからpullするとunstaged changesがrebaseをブロックする。
• `git config pull.rebase true` でデフォルト動作をrebaseに設定しておくと `git pull` だけでOK。pre-pushフックに `git fetch && git rebase` を仕込むことで、pushの直前にリモートとの差分を取り込む設計も有効。
