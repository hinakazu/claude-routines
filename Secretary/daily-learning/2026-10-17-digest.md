**cronとPATH管理**
• cron/launchd起動のジョブは ~/.zshrc を読み込まないため、Homebrew などのPATHは未登録。exit 127 で無音終了する典型的な罠。
• 対策①スクリプト冒頭で `PATH=/usr/local/bin:/opt/homebrew/bin:$PATH` を明示。②全コマンドを絶対パスで呼ぶ。
• crontab変数展開（`PATH=$HOME/bin:$PATH`）は機能しない。デバッグには `env > /tmp/cron-env.txt` をcrontabに追加して環境を確認する。
• macOS Sequoia以降ではcronが実質機能しないケースあり。launchdへの移行が推奨だが、launchdでも同様のPATH対策が必要。

**`set -e` のサイレント終了とエラーハンドリング設計**
• `set -e` は条件式・論理演算子・サブシェル・コマンド置換（`$()`）内では適用されない。`local var=$(cmd)` と書くと `cmd` 失敗が隠れる（`local var; var=$(cmd)` と2行に分ける）。
• `set -o pipefail` を追記しないとパイプ途中の失敗が隠れる。算術 `((count--))` は0になると非ゼロを返す罠もある。
• 推奨パターン：`trap 'echo "Error at line $LINENO" >&2' ERR` でエラー行を記録し `trap 'cleanup' EXIT` でリソース解放。`set -E`（errtrace）でERRトラップを関数内に継承させる。

**git non-fast-forward push と rebase の操作順序**
• `git pull --rebase` はunstagedの変更があると失敗する。自動化スクリプトでは「commit → pull → push」の順を徹底する。
• `git pull --rebase --autostash` で未ステージ変更を自動スタッシュ→リベース→復元可能。`git config rebase.autoStash true` で常時有効化できる。
• CI自動化では fetch → rebase → push のサイクルを毎回新鮮な状態で実行するrunbookパターンが推奨。`--force-with-lease` は自分のブランチのみ使用可。
