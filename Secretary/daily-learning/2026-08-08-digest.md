**cronとPATH管理**
• cronジョブはユーザーの `.zshrc`/`.bash_profile` を一切読み込まないため、デフォルトPATHは `/usr/bin:/bin` のみ。Homebrewや `~/.local/bin` 等のパスが全滅し、コマンドが exit 127 で無音終了する。
• 確実な対策は3層構造：①crontabファイル冒頭で `PATH=/usr/local/bin:/usr/bin:/bin:...` を明示、②スクリプト内でコマンドを絶対パス指定（`/usr/local/bin/claude` 等）、③デバッグ時は `* * * * * env > /tmp/cron-env.txt 2>&1` で実際のcron環境変数を丸ごと記録して比較。
• macOSではcronよりlaunchdが推奨（スリープ中でも起動可能、イベントトリガー対応）。ただしlaunchdでもPATH問題は同様に発生するため、plistの `EnvironmentVariables` キーに明示的にPATHを記載する必要がある。

**`set -e` のサイレント終了とエラーハンドリング設計**
• `set -e` はif文の条件部分・`&&`/`||` チェーン・パイプライン途中のコマンドでは**発動しない**という重大な盲点がある。また `(( i++ ))` が0を返す場合もスクリプトが即終了する（算術式が「false」扱い）。
• 推奨パターンは `set -euo pipefail` の3点セット：`-e`（コマンド失敗で即終了）＋ `-u`（未設定変数をエラー扱い）＋ `-o pipefail`（パイプ途中のエラーを捕捉）。さらに `set -E`（errtrace）と `trap 'echo "ERROR at line $LINENO, exit $?" >&2' ERR` を組み合わせることで、エラー発生行番号をログに残せる。
• コマンド置換 `out=$(false)` 内のエラーは `set -e` が届かないため、`shopt -s inherit_errexit`（bash 4.4+）で補う必要がある。特定コマンドのエラーを意図的に無視したい場合は `command || true` または `command || :` を使う。

**git non-fast-forward push と rebase の操作順序**
• non-fast-forwardエラーの本質は「リモートブランチがローカルより先に進んでいるのにpushしようとした」こと。自動化スクリプトで複数箇所からpushする場合、操作順序は必ず `git fetch` → `git rebase` または `git merge` → ローカル変更 → `git add` → `git commit` → `git push` の順を守る。
• `git pull --rebase` はリモートの変更を取り込みつつローカルのコミットをその上に積み直すため、マージコミットが残らずログが線形になる。ただしunstaged changesがある状態でrebaseするとブロックされるため、**pull前に必ず `git status --porcelain` で変更がないことを確認**するか、`git stash` で退避してから実行する。
• 自動化スクリプトでのforce pushは `--force-with-lease` を使う（`--force` はリモートの他者コミットを破壊しうる）。Mergifyなどのツールを使えばPRのリベースを自動化でき、「全員が手動でrebaseを忘れずに実行する」という属人的なルールをなくせる。
