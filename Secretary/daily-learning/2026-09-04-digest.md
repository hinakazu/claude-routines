**cronとPATH管理**
• cronジョブはデフォルトで `PATH=/usr/bin:/bin` しか持たず、`.zshrc` や `.bashrc` は一切読み込まれない。Homebrewバイナリ（`/opt/homebrew/bin`）やカスタムツールは完全に見えない状態で実行される。
• 解決策は3層：①crontabの先頭で `SHELL=/bin/bash` と `PATH=/opt/homebrew/bin:/usr/local/bin:/usr/bin:/bin` を明示指定、②バイナリはスクリプト内で絶対パス使用、③ラッパースクリプトで環境変数をセットしてから本体を呼ぶ。変数展開（`PATH=$PATH:...`）はcron実装によって動かない場合があるため禁止。
• macOSではAppleがcronを非推奨としlaunchdへ移行を推奨。launchdはPlist内で `EnvironmentVariables` キーで環境変数を宣言できるため、シェル依存を断ち切れる。スリープ/ウェイク後の実行漏れも防げる。

**`set -e` のサイレント終了とエラーハンドリング設計**
• `set -e` は「エラーで即終了」するが条件文・`||/&&` チェーン・サブシェル内では無効化される。`if cmd; then ... fi` の `cmd` が失敗してもスクリプトが継続するという反直感的な動作が原因究明を困難にする。
• 推奨パターンは `set -euo pipefail` の三点セット：`-e`=エラー即終了、`-u`=未定義変数をエラー扱い、`-o pipefail`=パイプライン内の失敗を伝播。さらに `set -E` と `trap 'echo "Error at line $LINENO: $BASH_COMMAND (exit $?)" >> /var/log/myscript.err' ERR` を組み合わせることで関数・サブシェルにもトラップを継承させ、ログに失敗行番号・コマンド・終了コードを残せる。
• `trap cleanup EXIT` を加えると正常・異常どちらの終了でもテンポラリファイル削除・プロセス終了などクリーンアップが保証される。

**git non-fast-forward push と rebase の操作順序**
• non-fast-forwardエラーは「リモートにローカルが知らないコミットが追加された後に push しようとした」ときに発生。自動化スクリプトでCIコミットや別端末からのpushが先行するとこの状態になる。
• 正しい操作順序は `git pull --rebase origin <branch>` → ファイル変更 → `git add` → `git commit` → `git push`。pull前にunstagedな変更があると rebase がブロックされるため、変更はpullの後に加える。`--force-with-lease`（`--force`は禁止）は安全な強制pushとして、rebase後にリモートが別の誰かに書き換えられていないか確認してから上書きする。
• 自動化スクリプトへの組み込みとしては pre-pushフックに `git fetch && git rebase origin/$(git branch --show-current)` を仕込む方法と、push失敗時に `git pull --rebase` してリトライするエラーハンドリングの2パターンが有効。
