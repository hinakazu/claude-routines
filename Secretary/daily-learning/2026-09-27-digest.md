**cronとPATH管理**
• cronジョブはユーザーの `.bashrc`/`.zshrc` を一切読まない。デフォルトPATHは `/usr/bin:/bin` のみで、`/usr/local/bin` 等にインストールしたコマンドは見つからずexit 127で無音終了する。
• crontabの先頭行に `PATH=/usr/local/bin:/usr/bin:/bin:/opt/homebrew/bin` 等を明示することで全ジョブに適用できる。
• ラッパースクリプト方式が本番推奨：スクリプト冒頭で環境変数を明示設定し、cronからはそのラッパーを絶対パスで呼ぶ。
• macOSのlaunchdでは `EnvironmentVariables` キーでplist内に直接PATHを記述でき、crontabより確実に環境変数を制御できる。

**`set -e` のサイレント終了とエラーハンドリング設計**
• `set -e` は `if`/`elif` の条件部・`while`/`until` ループ条件・`&&` `||` リスト内（最終コマンド以外）では発動しない。特に `call && true` は失敗を検出せず `true && call` は検出するという非対称な動作が落とし穴。
• 推奨パターンは `set -eE`（errtrace）＋ `trap 'echo "Error at line $LINENO" >&2' ERR`。`-E` を付けることでERRトラップが関数・サブシェル内にも継承される。
• コマンド置換内（`$(...)`）ではデフォルトで `-e` が継承されない。Bash 4.4以降の `inherit_errexit` オプションを使うか、置換内のエラーを明示的にチェックする必要がある。

**git non-fast-forward push と rebase の操作順序**
• 自動化スクリプトでの正しい順序は `git stash` → `git pull --rebase origin main` → `git stash pop` → `git add` → `git commit` → `git push`。uncommitted changesがある状態でrebaseするとブロックされる。
• `git pull --rebase` は履歴を線形に保つが、共有ブランチへの適用は禁止（他者のcheckoutを壊す）。ローカルフィーチャーブランチ専用。
• non-fast-forwardエラーの根本原因は「リモートに自分が知らないコミットが先行している」こと。対策はpush前の `git fetch` ＋ 差分確認を自動化スクリプトに組み込むこと。
