**cronとPATH管理**
• cronが実行する環境は `/usr/bin:/bin` のみの最小PATHで動作し、`.zshrc` や `.bashrc` は一切読み込まれない。`/Applications/cmux.app/...` など独自パスを追加したコマンド（`claude` 等）はexit 127でサイレント失敗する
• 解決策は3段階：①crontabファイルの先頭に `PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:/custom/path` を明示 ②スクリプト内で `source ~/.profile` または絶対パスでコマンド指定 ③`crontab -e` でPATHを設定する際は変数展開（`$HOME`）は使えないため完全パスで記述
• デバッグ方法：cron実行ログを `* * * * * /path/script.sh >> /tmp/cron.log 2>&1` と必ずリダイレクトし、`env > /tmp/cron_env.log` で実際の環境変数を確認する

**`set -e` のサイレント終了とエラーハンドリング設計**
• `set -e` は万能ではない：`if`/`while`/`until` 条件内・`||` や `&&` の左辺・`!` で否定されたコマンドでは **発火しない**。`(( i++ ))` のような算術式がゼロ評価でも終了する罠もある
• 推奨パターンは `set -eEuo pipefail` の組み合わせ：`-E` でERRトラップを関数・サブシェル内でも継承させ、`-o pipefail` でパイプ途中の失敗も捕捉。`trap 'echo "ERROR: line $LINENO, exit $?" >&2' ERR` でログ付き終了を実現
• 例外的に失敗を許容するコマンドには `command || true` を付与。変数参照は `${VAR:-default}` で安全にデフォルト値を設定し `-u` との衝突を回避する

**git non-fast-forward push と rebase の操作順序**
• 自動化スクリプトでの正しい順序は `git stash -u` → `git pull --rebase origin main` → ファイルコピー・編集 → `git add` → `git commit` → `git stash pop`（必要なら）→ `git push`。commitの前にpullを挟まないとnon-fast-forwardになる
• unstaged changesチェックを自動化に組み込む：`git diff --quiet || git stash -u` でプル前に未コミット変更を自動退避。`git config --global rebase.autoStash true` を設定すると pull --rebase が自動でstash/unstashする
• `git diff-files --quiet` でstaged以外の変更を検出し、変更ありなら `exit 1` で早期失敗させると操作ミス由来のCIエラーを未然防止できる
