**cronとPATH管理**
• cronは最小限のPATH（`/usr/bin:/bin`）しか持たず、`.zshrc` や `.bashrc` は読み込まれない。スクリプト冒頭で `PATH=/usr/local/bin:/usr/bin:/bin:/Applications/cmux.app/Contents/Resources/bin` のように明示するのが最確実な回避策。
• crontabファイルの先頭に `PATH=...` を書くと全ジョブに適用できるが、`$PATH` 展開は一部cronでサポートされないため変数展開に頼らない。
• macOSではAppleがcronをdeprecatedとしてlaunchdを推奨。launchdはplistの `EnvironmentVariables` キーで環境変数を宣言でき、スリープ中のジョブ実行漏れも防げる。

**`set -e` のサイレント終了とエラーハンドリング設計**
• `set -e` は `if`条件部・`&&`/`||`リスト・`while`条件部では発動せず、コマンド置換（`$(...)`）内では `errexit` と `ERR` トラップが自動無効化される。`shopt -s inherit_errexit` で継承を有効化する必要がある。
• `set -E`（errtrace）を有効にすると `ERR` トラップが関数・サブシェルにも伝播する。`trap 'handle_error "$?" "${BASH_COMMAND}" "${FUNCNAME[0]}:${LINENO}"' ERR` のパターンでスタックトレース付きのエラーログを残せる。
• 実践的な出発点は `set -euo pipefail` + `trap '...' ERR` のセット。`set -e` はあくまで「補助ツール」で、重要なコマンドは明示的に終了コードをチェックする設計が堅牢。

**git non-fast-forward push と rebase の操作順序**
• 自動化スクリプトでのgit操作の正しい順序は `pull → ファイル操作（cp等）→ add → commit → push`。逆順（ファイル操作→pull）にするとunstaged changesが発生し `git pull --rebase` がブロックされる。
• non-fast-forwardエラーが発生したら `git fetch origin` + `git rebase origin/main` で解消。force pushは避け、必要な場合は `git push --force-with-lease` を使う（他者の変更を誤上書きしない）。
• 複数箇所からpushが発生するリポジトリでは、スクリプト冒頭で `git stash -u` して末尾で `git stash pop` する、またはpull時に常に `--rebase` フラグを付けることでヒストリをリニアに保てる。
