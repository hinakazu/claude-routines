**cronとPATH管理**
• cronはユーザーの `.zshrc`/`.bashrc` を読み込まないためPATHは `/usr/bin:/bin` のみ。crontabの先頭に `SHELL=/bin/bash` と `PATH=/usr/local/bin:/usr/bin:/bin:/usr/sbin:/sbin` を明記するのが最低限の対策
• ラッパースクリプト方式が最も安全：`0 3 * * * /opt/scripts/env-wrapper.sh` のようにPATH設定を内包したラッパー経由で実行。手動でもテスト可能で自己文書化にもなる
• `PATH=$PATH:/new/path` の変数展開はcron実装によっては動作しないため、フルパス直書きが安全。`/etc/environment` はシステム全体のcronデフォルト環境として読み込まれる

**`set -e` のサイレント終了とエラーハンドリング設計**
• `set -e` は `if`・`||`・`&&` などの条件式の中では発火しないという重大な落とし穴がある。`grep` の戻り値1（マッチなし）でも即終了するケースも
• `set -eo pipefail` + `trap ERR` の組み合わせが本番スクリプトの標準パターン。`trap`ハンドラーで `$BASH_COMMAND`（失敗コマンド名）・`$BASH_LINENO`（行番号）・`$?`（終了コード）をログに記録する
• `-E`（errtrace）オプションを追加するとサブシェルや関数内でも ERR トラップが継承される。`trap EXIT` で終了時の確実なクリーンアップも実装すべき

**git non-fast-forward push と rebase の操作順序**
• `git pull --rebase --autostash` が自動化スクリプトの正解。`--autostash` がrebase前に自動stash・rebase後に自動unstashするため、dirty worktreeでも安全にpullできる
• `git config --global rebase.autoStash true` でグローバル設定にしておくと `git pull --rebase` だけで自動stash有効になり、スクリプト内の手動stash処理が不要になる（Git 2.6以降）
• 正しい操作順序は「`git pull --rebase --autostash` → ファイル操作 → `git add` → `git commit` → `git push`」。共有ブランチへのrebaseは履歴を書き換えるため禁止
