**cronとPATH管理**
• cronジョブの環境は完全独立で `PATH=/usr/bin:/bin` のみ。`.bashrc`/`.zshrc` は読み込まれないため `claude` 等カスタムバイナリはパスが通らない。スクリプト冒頭で `PATH=/usr/local/bin:/usr/bin:/bin:/Applications/cmux.app/Contents/Resources/bin` と絶対パスで明示指定するのが唯一の確実な解決策。
• `PATH=$PATH:/some/path` の変数展開はcron内では動作しないディストリビューションがあるため使用禁止。必ず全パスを手書きで列挙する。
• macOSではcronは非推奨。`launchd`（`~/Library/LaunchAgents/*.plist`）がネイティブ代替で、スリープ復帰後の遅延実行も保証される。`plutil -lint` でplist検証が可能。

**`set -e` のサイレント終了とエラーハンドリング設計**
• `set -e` 単独では `&&`/`||` 連鎖・サブシェル・コマンド置換でエラーが無視される。確実なパターンは `set -euo pipefail` + `set -E`（errtrace）+ `shopt -s inherit_errexit` の組み合わせ。
• `trap 'handle_error "$?" "${BASH_COMMAND}" "${FUNCNAME[0]}(${BASH_SOURCE[0]}:${LINENO})"' ERR` で失敗コマンド名・終了コード・行番号をすべてログに記録できる。
• `trap cleanup EXIT` で一時ファイル削除・バックグラウンドプロセス終了をエラー時でも確実に実行。`&&`/`||` 内ではERRトラップが発動しないため条件分岐は `if` 文で明示チェックする。

**git non-fast-forward push と rebase の操作順序**
• 自動化スクリプトの安全な順序は「`git stash -u` → `git pull --rebase` → ファイルコピー等の操作 → `git stash pop` → `git add` → `git commit` → `git push`」。unstaged changesがある状態でpullすると衝突か拒否が発生する。
• `git config pull.rebase true` をグローバル設定しておくとマージコミットが発生せず履歴が線形に保たれる。
• non-fast-forward pushが発生した場合はpull→retryロジックを実装する。`git powercommit` 等のツールがこのパターンを自動化しており参考実装として有用。
