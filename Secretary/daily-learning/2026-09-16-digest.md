**cronとPATH管理**
• cronジョブのデフォルトPATHは `/usr/bin:/bin` のみ。ユーザーの `.zshrc` や `.bash_profile` は読み込まれないため、`/opt/homebrew/bin` や `/Applications/cmux.app/Contents/Resources/bin` 等のカスタムパスが存在しない。スクリプト冒頭で `PATH=/opt/homebrew/bin:/usr/local/bin:/usr/bin:/bin` を明示するか、crontab自体に `PATH=...` 行を追加するのが最も確実。
• macOS標準の `launchd` はcronより優れたPATH管理が可能。各エージェントごとに独立した `EnvironmentVariables` を持ち、Apple Silicon Macでは `/opt/homebrew/bin` を明示的に追加する必要がある。スリープ中に実行を逃してもwake時にリカバリする機能もあり、macOSの自動化にはcronよりlaunchdが推奨。
• crontabにはSHELLも明示的に指定する: `SHELL=/bin/bash`。デフォルトは `/bin/sh` のため、bash固有の構文が使えず予期せぬエラーの原因になる。

**`set -e` のサイレント終了とエラーハンドリング設計**
• `set -e` は `&&` / `||` チェーン・`if` 条件部・パイプ中間コマンドでは機能しない。`true && some_command` でエラーになるが `some_command && true` ではならない、という非直感的な挙動がある。`set -euo pipefail` をセットで使うことでパイプ失敗も捕捉できる。
• `trap 'handle_error "$?" "${BASH_COMMAND}" "${LINENO}"' ERR` を組み合わせると条件分岐・サブシェル含め確実にエラーを捕捉できる。`-E` フラグ（errtrace）を加えると関数内ERRトラップ継承も有効。実装例: `trap 'printf "✘ %s: %s at line %s\n" "${0##*/}" "${BASH_COMMAND}" "${LINENO}" >&2; exit 1' ERR`
• `trap cleanup EXIT` でスクリプト終了時（正常・異常問わず）にリソースクリーンアップを実行するパターンが実務的に重要。一時ファイル削除、バックグラウンドプロセス終了等に使える。

**git non-fast-forward push と rebase の操作順序**
• 自動化スクリプトでのgit操作の正しい順序: `git pull --rebase` → ファイル変更 → `git add` → `git commit` → `git push`。未コミット変更がある状態で `git pull --rebase` を実行するとブロックされるため、変更前にpullすることが必須。
• 複数箇所からpushが発生するリポジトリでは `git pull --rebase` が特に有効。通常の `git pull` よりも線形なコミット履歴を維持でき、CIでどのコミットがビルドを壊したか特定しやすい。
• 自動化スクリプトでuncommitted changesを安全に扱うには `git stash -u` → `git pull --rebase` → `git stash pop` のパターンが堅牢。ただしコンフリクトが起きる可能性を考慮したエラー処理も追加すること。
