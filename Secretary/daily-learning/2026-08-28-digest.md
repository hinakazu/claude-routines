**cronとPATH管理**
• cronジョブが起動する環境のデフォルトPATHは `/usr/bin:/bin` のみ。ターミナルで動くコマンドが無音終了する原因の大半がこれ。
• 対策はcrontabの先頭に `PATH=/usr/local/bin:/usr/bin:/bin:/opt/homebrew/bin` を変数展開なしで直書きするか、スクリプト内でPATHを明示設定すること。
• macOSでは `cron` はDeprecated。`launchd` がApple公式の代替で、`EnvironmentVariables` キーでエージェントごとにPATHを独立設定でき、スリープ中のジョブ実行漏れも防げる（cronはスリープ中のジョブをスキップするがlaunchdは起動時に自動実行）。

**`set -e` のサイレント終了とエラーハンドリング設計**
• `set -e` は `if`文・`||`・`&&`チェーン・サブシェル内のコマンドでは機能せず、スクリプトが無音終了するケースがある（例: `cmd && true` は失敗しても終了しない）。
• 推奨パターンは `set -eE`（errtrace付き）+ `trap ERR` の組み合わせ。`set -E` により関数・サブシェル内のERRトラップが継承される。
• 後始末は `trap cleanup EXIT` で必ず設定することで、エラー・正常終了どちらの場合でも一時ファイル削除や状態復元が保証される。

**git non-fast-forward push と rebase の操作順序**
• non-fast-forwardエラーはローカルとリモートの履歴が乖離したときに発生。自動化スクリプトでは「変更コピー → push」の前に必ず `git pull` を入れること。
• 正しい順序: `pull` → ファイル変更・コピー → `commit` → `push`。rebaseを使う場合は `git pull --rebase` でローカルコミットをリモート履歴の先頭に積み直せる。
• `git config pull.rebase true` を設定しておくと `git pull` が自動的にrebaseモードで動作。複数箇所からpushするリポジトリではこの設定が安全。
