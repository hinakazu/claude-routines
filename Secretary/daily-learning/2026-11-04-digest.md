**cronとPATH管理**
• cronジョブはユーザーの `.zshrc` や `.bashrc` を読み込まない。macOSのcronはデフォルトで `PATH=/usr/bin:/bin` のみ。対策は①crontab冒頭に `PATH=...` を明示、②スクリプト内で絶対パスを使う、③`SHELL=/bin/bash` を宣言してデフォルトsh問題も回避、の3点セット。
• macOSではAppleが公式にlaunchdを推奨。launchdはPCスリープ中に逃した実行を起動後に1回実行してくれる（cronはスキップ）。plistのEnvironmentVariablesにPATHを設定できる。Apple Silicon環境では `/opt/homebrew/bin` を忘れずに追加。
• デバッグ手法：`env > /tmp/cron_env.txt` でcronの環境をダンプして手動実行時の `env` と比較するとPATH・ロケール・タイムゾーンのズレが一発で可視化できる。

**`set -e` のサイレント終了とエラーハンドリング設計**
• `set -e` 単体では「if条件内のコマンド」「`&&`/`||` チェーン」「パイプラインの途中コマンド」は終了コードをトリガーしない。安全な最小セットは `set -euo pipefail`。`-u` は未定義変数エラー化、`-o pipefail` はパイプの途中失敗を伝播させる。
• `((i++))` が0に評価されると非ゼロ終了でスクリプトが予期せず終了するトラップがある。算術式には `|| true` を後置するかブロックを `set +e` / `set -e` で囲む。`local` / `export` / `declare` も代入右辺のコマンド失敗を隠蔽するので注意。
• ERR trap と EXIT trap を使い分ける：`trap 'echo "FAILED at line $LINENO"' ERR` で失敗箇所をログ、`trap 'rm -f /tmp/work$$' EXIT` で後片付け。ERR trapはERRを無視するコンテキストでは発火しない点に注意（ERR trapが発火しない箇所 = set -eも終了しない箇所と対応）。

**git non-fast-forward push と rebase の操作順序**
• 自動化スクリプトでの正しい順序：`git pull --rebase --autostash → 変更を加える → git add → git commit → git push`。`--autostash` を付けると未コミットの変更を自動スタッシュ→rebase→ポップしてくれるため、変更を加えた後にpullしてもブロックされない。
• 並行実行（CI複数ジョブなど）では1回のpullでは不十分で、pushが失敗したら再度pull-rebaseを試みる有限リトライループが堅牢。例：`for i in 1 2 3; do git push && break || git pull --rebase; done`
• `pull.rebase=true` と `rebase.autoStash=true` をリポジトリの `.gitconfig` に設定しておくとチーム全員のデフォルト動作を統一できる。個人設定ではなくリポジトリ設定（`git config --local`）で管理すると自動化スクリプトも同じ挙動になる。
