**cronとPATH管理**
• cronジョブはユーザーの .zshrc/.bashrc を読み込まないため、デフォルトPATHは `/usr/bin:/bin` のみ。nvm・pyenv・Homebrew等のツールは見つからずexit 127でサイレント失敗する
• 解決策は3つ: (1) crontabファイル冒頭に `PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin` を明記 (2) スクリプト内でフルパスを使用 (3) 環境ファイルをスクリプト内でsource
• ログが `/dev/null` に捨てられているとデバッグ不能。必ず `>> /var/log/cron.log 2>&1` でstdout/stderrを同時捕捉すること

**`set -e` のサイレント終了とエラーハンドリング設計**
• `set -e` は条件式・`||`/`&&` チェーン・サブシェル内では発動せず、想定外の場所でサイレント続行する諸刃の剣
• 推奨ベースラインは `set -euo pipefail` の3点セット: errexit（エラー即終了）＋ nounset（未定義変数を検出）＋ pipefail（パイプ途中の失敗を検出）
• `trap 'echo "Error at line $LINENO: $BASH_COMMAND" >&2' ERR` を組み合わせることで、どのコマンドが失敗したかを明示的にログ出力できる

**git non-fast-forward push と rebase の操作順序**
• non-fast-forward拒否は「ローカルの認識するリモート状態」と「実際のリモート状態」が一致しないときGitが安全のため発動。複数箇所からpushが走る自動化では常に発生しうる
• 正しい操作順序: `git pull --rebase origin <branch>` → 変更ファイルをコピー/生成 → `git add` → `git commit` → `git push`。pullを後回しにすると unstaged changes でrebaseがブロックされる
• `git config --global pull.rebase true` でデフォルトをrebase pullにしておくと、merge commitが積み上がらず履歴がクリーンに保てる
