**cronとPATH管理**
• cronはユーザーの `.zshrc`/`.bashrc` を読み込まない最小限の環境で起動するため、`/Applications/cmux.app/.../bin` などのカスタムPATHが未登録になり `command not found (exit 127)` でサイレント失敗する。対策は①crontabヘッダーに `PATH=/usr/local/bin:/usr/bin:/bin:...` を明示 ②各スクリプト冒頭で `export PATH` を再定義 ③バイナリは絶対パスで呼び出すの3択。
• macOS Sequoia以降では launchd がcronを管理しているが、cron自体が動かない報告も確認されており、本格的な自動化には `launchd` の plist を直接使う方が確実。デバッグは `* * * * * env > /tmp/cron_env.log` で環境変数を丸ごとダンプして確認。
• stdoutとstderrをログファイルにリダイレクトしないとメーラー未設定環境では出力が無音廃棄される。`>> /tmp/myjob.log 2>&1` は必須。

**`set -e` のサイレント終了とエラーハンドリング設計**
• `set -e` は一見安全に見えるが重要な例外が多い。①`if`/`while` 条件部 ②`!` 否定 ③`&&`/`||` 連結の中では失敗してもexitしない。④コマンド置換 `$(...)` 内の失敗も素通りする。⑤ `((count--))` は結果が0になると終了コード1を返しスクリプトが即終了する（`|| true` で回避）。
• 推奨パターンは `set -euo pipefail` ＋ ERRトラップ。`trap 'echo "FAILED: line $LINENO cmd=$BASH_COMMAND" >> error.log' ERR` でサイレント終了を防ぐ。`set -E`（errtrace）を追加するとERRトラップが関数・サブシェルにも伝播する。
• `local var=$(cmd)` は宣言と代入を同時にやると `cmd` の終了コードが隠れるため危険。宣言と代入を必ず分けること。

**git non-fast-forward push と rebase の操作順序**
• 自動化スクリプトでgit操作をする場合、必ず `git status` で uncommitted changes がないことを確認してから `pull --rebase` を実行する。変更がある場合は `git stash -u → pull --rebase → git stash pop` の順序で処理する。
• `git config pull.rebase true` をスクリプト冒頭か `.gitconfig` に設定しておくと、引数なしの `pull` でrebaseが使われ操作ミスを防げる。
• rebase後のpushはコミットSHAが変わるため通常 `--force` が必要になるが、他の人が同じブランチにpushしていた場合に上書きするリスクがある。`--force-with-lease` を使うとリモートの最新状態を確認してから強制pushするため安全。
