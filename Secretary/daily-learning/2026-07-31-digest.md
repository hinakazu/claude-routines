**cronとPATH管理**
• cronはユーザーの`.zshrc`や`.bash_profile`を読まず、デフォルトPATHは`/usr/bin:/bin`のみ。HomebrewツールやNode.js等はすべて不可視になる
• 最も確実な対策はcrontabの先頭で`PATH=/usr/local/bin:/usr/bin:/bin`を明示宣言するか、スクリプト内でフルパス（`/opt/homebrew/bin/node`等）を使うこと。crontab内で`$PATH`変数展開は動作しないため注意
• macOSではlaunchdの`plist`ファイルに`EnvironmentVariables`辞書でPATHを明記するのが正しい方法。`launchctl setenv`は非推奨
• デバッグ手順: crontabに`env > /tmp/cron_env.txt 2>&1`を追加してcron環境変数をダンプし、`env -i HOME=/root PATH=/usr/bin:/bin /bin/bash script.sh`で手動再現する

**`set -e`のサイレント終了とエラーハンドリング設計**
• `set -e`はif/while条件式、`&&`/`||`チェーン内、`!`（否定）コマンドでは発火しない。`result=$(failing_func)`のようなコマンド置換でもサブシェルの`set -e`が無効になる
• `local var=$(cmd)`はlocalが常にexit 0を返すため、内側の失敗を完全にマスクする。`local var`と`var=$(cmd)`を2行に分けて書くことで回避できる
• 本番スクリプトの推奨冒頭: `set -eEuo pipefail` + `shopt -s inherit_errexit`（bash 4.4+）。パイプライン失敗・未定義変数・関数内ERRトラップ継承・コマンド置換のerexit継承をすべてカバー
• ERRハンドラーのテンプレート: `trap 'echo "Error on line $LINENO: $BASH_COMMAND (exit $?)" >&2' ERR` で失敗コマンド・行番号・終了コードを標準エラーに記録できる

**git non-fast-forwardとrebase操作順序**
• non-fast-forwardエラーはローカルとリモートが分岐したとき発生。Gitはリモートのコミットを上書きしないためpushを拒否する
• 自動化スクリプトの正しい操作順序: `git pull --rebase origin <branch>` → 作業・ファイル配置 → `git add` → `git commit` → `git push`。pull前にcommitするとrebaseがブロックされる原因になる
• `git config --global pull.rebase true`を設定しておくと`--rebase`フラグなしでも常にrebase動作になる。CI環境では`.gitconfig`や`GIT_CONFIG_GLOBAL`で設定する
• コンフリクト発生時は自動解決せず非ゼロで終了してアラートするのが正しい設計。ブランチ保護ルールの「マージ前に最新化を要求」設定でリモートへの分岐到達を事前に防げる
