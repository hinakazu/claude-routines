**cronとPATH管理**
• cronジョブは `.zshrc` / `.bash_profile` を読み込まないため、Homebrew（`/opt/homebrew/bin`）や自作スクリプト（`/Applications/cmux.app/.../bin`）など非標準PATHが全滅する。対策はスクリプト冒頭で `PATH=/opt/homebrew/bin:/usr/local/bin:/usr/bin:/bin` を明示的にフルパス記述すること（変数展開 `PATH=$PATH:...` はcron実装によっては展開されないため NG）。
• macOSでは cron はAppleに非推奨とされており、`launchd` が公式の後継。launchdはジョブ定義のplistに `<key>EnvironmentVariables</key>` で変数をジョブごとに宣言でき、sleep/wake にも対応、ログもシステムログと統合される。
• 自動化スクリプトが「手動では動くのにcronで動かない」場合、まず `env > /tmp/cron-env.txt` をcronから実行して実際の環境変数を確認するデバッグ手順が有効。

**`set -e` のサイレント終了とエラーハンドリング設計**
• `set -e` は if文・`||`/`&&`チェーン・サブシェル内では**自動的に抑制**される。そのため「失敗しても止まらない」局面が多く、デバッグが困難になる。2025〜2026年の本番スクリプトの標準パターンは `set -euo pipefail`：`-u` は未設定変数をエラー化、`-o pipefail` はパイプ内の途中失敗を終了コードに伝播させる。
• `trap 'echo "ERROR: line $LINENO, cmd: $BASH_COMMAND, exit: $?" >&2' ERR` を組み合わせると、`set -e` が抑制される文脈でも失敗をキャッチしてログに残せる。さらに `set -E`（errtrace）でサブシェル・関数内にも ERR トラップを継承できる。
• 一時ファイルの後始末には `trap cleanup EXIT` が有効。正常終了・異常終了・シグナル受信のいずれでも実行される。

**git non-fast-forward push と rebase の操作順序**
• 複数箇所からコミット・pushが走る自動化リポジトリで頻発するパターン：ローカルに未コミット変更がある状態で `git pull --rebase` を実行するとrebaseがブロックされる。正しい順序は **「pull → ファイル配置 → commit → push」**。ファイル配置後にpullすると unstaged changes が残り rebase が失敗する。
• `git pull --rebase origin <branch>` は、リモートの最新コミットの上にローカルコミットを"積み直す"操作。merge コミットを作らないため履歴が線形に保たれ、自動化スクリプトに適している。
• 自動化での再発防止策：pre-push フックに `git fetch origin && git status` を仕込んでコンフリクト前に検知する、またはCI/CDではPR経由のマージに統一することで non-fast-forward を原理的に排除できる。
