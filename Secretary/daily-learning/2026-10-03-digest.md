**cronとPATH管理**
• cronのデフォルトPATHは `/usr/bin:/bin` のみ。`/usr/local/bin` や独自インストールパスは未登録のため、コマンドがexit 127で無音終了する
• 最も確実な対策はcrontab冒頭に `PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin` を明示的に書くか、スクリプト先頭で `source /etc/profile` を呼ぶこと
• シェバング `#!/bin/bash -l` でログインシェルとして実行すれば `.bash_profile` も読み込まれる

**`set -e` のサイレント終了とエラーハンドリング設計**
• `set -e` は条件文・`||`/`&&` チェーン・サブシェル内では機能しない。関数内の失敗がスクリプトを終了させてもERRトラップが呼ばれないケースがある
• 解決策は `set -E`（errtrace）の追加。`set -eEuo pipefail` + `trap 'echo "Error at line $LINENO"' ERR` の組み合わせが鉄板パターン
• コマンド置換にも errexit を継承させるには `shopt -s inherit_errexit` が必要（bash 4.4+）

**git non-fast-forward push と rebase の操作順序**
• 自動化スクリプトでの正しい順序は `git pull --rebase → ファイル操作 → git commit → git push`。pullより先にファイル変更するとunstaged changesがrebaseをブロックする
• `git config --global pull.rebase true` でpull時のrebaseをデフォルト化でき、マージコミットなしでリニアな履歴を維持できる
• pushが non-fast-forward で失敗した際は `pull → リトライ` のループロジックを組み込む。`git-auto-commit-action` は100回リトライするパターンを採用している
