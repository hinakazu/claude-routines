**cronとPATH管理**
• cronのデフォルトPATHは `/usr/bin:/bin` のみ。`.zshrc`や`.bashrc`は読み込まれないため、カスタムインストールした`claude`などのコマンドはexit 127で無音失敗する。
• スクリプト冒頭で `export PATH=/usr/local/bin:/opt/homebrew/bin:$PATH` のように明示的に設定するか、crontabの先頭行に `PATH=...` を記載するのが最も確実。
• `SHELL=/bin/bash` をcrontabに明示しないと `/bin/sh` で実行されbash固有構文が静かに失敗する。コマンドはすべて絶対パスで指定し、ログを必ず残す設計にする。

**`set -e`のサイレント終了とエラーハンドリング設計**
• `set -euo pipefail` の3点セットが2026年の推奨標準。`-u`で未定義変数エラー検出、`-o pipefail`でパイプ途中の失敗も拾う。
• `set -e` の「穴」：`if`条件内、否定コマンド（`! cmd`）、`&&`/`||`チェーン内では失敗しても終了しない。`$(...)` はデフォルトでset -eを継承しない（Bash 4.4以降は`inherit_errexit`で解消可能）。
• `trap 'echo "エラー: line $LINENO" >&2' ERR` でどこで失敗したかログを残す。ERR trapはset -eが抑制される文脈では発火しないため、`trap cleanup EXIT`と組み合わせて後処理を確実にする。

**git non-fast-forward pushとrebase操作順序**
• 自動化スクリプトでgitを扱うときの鉄則は「commitの前にpull」。正しい順序は `git status → git pull --rebase → ファイル操作 → git add → git commit → git push`。
• `git pull --rebase`の前に作業ツリーが汚れていると rebase がブロックされる。`--autostash`フラグを使うかスクリプト先頭で`git stash`して回避。rebaseは他人と共有済みのブランチには使わない。
• `git rerere`（reuse recorded resolution）を有効化すると同じコンフリクトを2回手動解消しなくて済む：`git config rerere.enabled true`。自動化スクリプトでは`set -e`と組み合わせてfail fastにし、各ステップをログに残す。
