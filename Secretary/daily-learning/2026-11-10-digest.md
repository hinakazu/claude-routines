**cronとPATH管理**
• cronジョブはユーザーの`.zshrc`/`.bash_profile`を読み込まないため、スクリプト冒頭で `export PATH=/usr/local/bin:/usr/bin:/bin:/your/custom/path:$PATH` と明示的に指定することが必須。`crontab -e`の冒頭に`PATH=...`を書く方法もあるが、変数展開（`$HOME`等）は効かないため完全なパスを書く必要がある。
• `env -i bash --noprofile --norc`でクリーンな環境を再現しスクリプトを手動テストすることでcron環境を事前に検証できる。macOSではlaunchdが代替として推奨されており、`launchd`はPATH等の環境変数を`EnvironmentVariables`キーで明示指定できる。
• cronの並列実行を防ぐには`flock -n /tmp/job.lock`を活用し、ログは`>> /var/log/myjob.log 2>&1`でstdout/stderrを両方記録する。

**`set -e` のサイレント終了とエラーハンドリング設計**
• `set -e`は`if文`・`||`・`&&`の内側では無効化されるため、条件チェック内のコマンド失敗がサイレントに無視される。`set -Eeuo pipefail`にすることで`set -E`（trap ERRの関数継承）と`-o pipefail`（パイプ途中の失敗を捕捉）も有効になる。
• コマンド置換（`result=$(failing_cmd)`）はデフォルトで`set -e`が伝播しない。Bash 4.4+なら`shopt -s inherit_errexit`を追加することで修正できる。
• 推奨テンプレート: `set -Eeuo pipefail` + `trap 'echo "Error at line $LINENO"' ERR` + `trap cleanup EXIT`。EXIT trapでクリーンアップ、ERR trapでログ出力と役割を分離する。

**git non-fast-forward push と rebase の操作順序**
• 自動化スクリプトでgit操作を行う場合、必ず `git pull --rebase` → ファイル変更 → `git add` → `git commit` → `git push` の順を守る。変更後にpullするとunstaged changesがrebaseをブロックする。
• スクリプト冒頭で`git diff --quiet && git diff --staged --quiet`を実行し、作業ツリーが汚れていないことを確認してから処理を開始する。汚れている場合は`git stash -u`で退避する。
• 繰り返し同じコンフリクトに遭遇する場合は`git config rerere.enabled true`（reuse recorded resolution）を設定すると自動解決の補助になる。コンフリクト発生時はスクリプトを失敗させて人間に委ねる設計が安全。
