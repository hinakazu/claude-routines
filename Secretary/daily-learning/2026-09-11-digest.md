**cronとPATH管理**
• cronはユーザーの `.zshrc` / `.bash_profile` を一切読まないため、実行時のPATHは `/usr/bin:/bin` だけになる。`claude` や `brew` でインストールしたコマンドは全て「コマンドが見つからない（exit 127）」で無音終了する
• 解決策は3層：①crontabファイル上部に `PATH=/opt/homebrew/bin:/usr/local/bin:/usr/bin:/bin` を1行追加する ②スクリプト冒頭に `export PATH=...` を書く ③全コマンドを絶対パスで指定する（最も堅牢）
• macOSでは `cron` より `launchd` が公式推奨。cronはMacがスリープ中の予定時刻をスキップするが、launchdはWake後に実行される。`.plist` ファイルで `EnvironmentVariables` キーを直接設定できるため、PATH問題も根本解決できる

**`set -e` のサイレント終了とエラーハンドリング設計**
• `set -e` は `if` の条件部・`||` / `&&` 連結・パイプの途中コマンド・コマンド置換 `$()` の内部では動作しない。これらの場面でコマンドが失敗しても無音で継続し、後続コマンドが誤った状態で動き続ける
• 本番スクリプトの推奨パターンは `set -euo pipefail` + `trap 'echo "Error line $LINENO: $BASH_COMMAND" >&2' ERR`。`$LINENO` で失敗行、`$BASH_COMMAND` で失敗コマンドが特定できるため、ログから原因を追跡できる
• `set -E`（errtrace）を追加すると ERR トラップが関数・サブシェル内にも伝播する。さらに `trap cleanup EXIT` を組み合わせると、正常終了・エラー終了どちらでも一時ファイルの削除やプロセス後始末が保証される

**git non-fast-forward push と rebase の操作順序**
• 自動化スクリプトでgit操作する場合の正しい順序は `git stash → git pull --rebase → git stash pop → ファイル操作 → git add → git commit → git push`。ファイルをコピーしてからpullするとunstaged changesがrebaseをブロックする
• `git config --global rebase.autoStash true` を設定すると、`git pull --rebase` 実行時に自動でstash/popが行われるため、順序ミスによるブロックが起きにくくなる。`pull.rebase true` と組み合わせるのが自動化での最善策
• non-fast-forwardエラーの根本原因は「リモートに自分が知らないコミットが増えた状態でpushしようとすること」。複数箇所から同じブランチにpushする自動化では、push直前にfetch/rebaseを必ず挟むことが必須
