**cronとPATH管理**
• cron は `.zshrc` / `.bash_profile` を一切読み込まず、デフォルトPATHは `/usr/bin:/bin` のみ。`claude` や `node` など独自パスのコマンドは exit 127 でサイレント失敗する。
• 最も確実な対策はcrontab冒頭に `PATH=/usr/local/bin:/usr/bin:/bin:...` を明示するか、ラッパースクリプト内で `source /etc/profile` してから本体を呼び出す構成にすること。
• 注意: crontab内では `PATH=$HOME/bin:$PATH` のような変数展開は機能しない。`BASH_ENV=/path/to/env.sh` を使うか絶対パスで記述する。

**`set -e` のサイレント終了とエラーハンドリング設計**
• `set -e` はコマンド失敗で即終了するが、`$(...)` コマンド置換内・`if/while` 条件部・`&&`/`||` チェーン内では発動しない盲点がある。
• `trap 'handle_error "$?" "${BASH_COMMAND}"' ERR` を併用すると `set -e` が発動しないケースも補足できる。`-E`（errtrace）オプションを追加すれば関数・サブシェル内にもトラップが継承される。
• 推奨セット: `set -euo pipefail` + `trap ERR` + `inherit_errexit` の3点セットで自動化スクリプトの信頼性が大幅に向上する。

**git non-fast-forward push と rebase の操作順序**
• 自動化スクリプトでのgit操作は「pull → 変更 → commit → push」の順序を厳守。未コミット変更がある状態でpullするとrebaseがブロックされるため、`git config --global rebase.autoStash true` を設定して自動stashを有効にするのが安全。
• Git 2.6以降の `--autostash` オプション（`git pull --rebase --autostash`）で未コミット変更を一時退避→rebase→復元まで自動化できる。
• 共有ブランチへの `git rebase`（history rewrite）は絶対NG。自動化スクリプトでは `git pull --rebase` は自分のブランチ限定で使うこと。
