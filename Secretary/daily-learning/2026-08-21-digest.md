**cronとPATH管理**
• cronジョブはユーザーの `.zshrc`/`.profile` を読み込まず、デフォルトPATHは `/usr/bin:/bin` のみ。Homebrewの `/opt/homebrew/bin` など追加パスは一切反映されない。
• 対策は3つ: ①crontabファイル冒頭で `PATH=...` を完全展開形式で宣言する（`PATH=$PATH:...` は変数展開されない実装がある）、②コマンドを絶対パスで記述する、③明示的なPATH設定を持つラッパースクリプトを介して呼び出す。
• macOSでは `cron` はAppleによって非推奨とされており、`launchd` に移行するのが現代的な選択。`launchd` は `EnvironmentVariables` でPATHを明示でき、Macのスリープ中に予定時刻を過ぎた場合も起動後に実行を補完する。

**`set -e` のサイレント終了とエラーハンドリング設計**
• `set -e` は `if`文・`||`/`&&` チェーン・サブシェル内のコマンドでは失敗時に終了しない。「安全に見えて実は素通り」になるケースが多い点に注意。
• 推奨の組み合わせは `set -Eeuo pipefail`：`-E` でERRトラップをサブシェル・関数にも継承、`-u` で未定義変数を検出、`-o pipefail` でパイプ途中の失敗も捕捉。
• `trap 'echo "ERROR: line $LINENO, cmd=$BASH_COMMAND, exit=$?" >> /tmp/script.log' ERR` を冒頭に書くことで、失敗したコマンド・行番号・終了コードをすべてログに残せる。「どこで止まったか分からない」問題が解消する。

**git non-fast-forward push と rebase の操作順序**
• `git pull --rebase` はワーキングツリーにunstagedな変更があると `Cannot pull with rebase: You have unstaged changes` で失敗する。自動化スクリプトでは実行順序を `pull → 編集 → commit → push` に統一することで回避できる。
• `git rebase --autostash`（または `git config --global rebase.autoStash true`）を設定すると、unstaged変更を自動でstash→rebase→stash popしてくれるため、スクリプト内で手動stashを書かずに済む。
• 自動化スクリプトでは `git pull --rebase --autostash` の1コマンドで「リモートとの同期＋ローカル変更の保全」を同時に達成できる。`git status` を pull の直前に挟んでワーキングツリーを確認するのも堅牢なパターン。
